# 单据审批流系统实施计划

## 1. 目标

基于第一个方案建设一套面向单据审批的流程系统：

- 前端新增 `packages/approval-workflow`，与现有低代码框架一样作为独立 npm 包维护和发布。
- 可选新增 `packages/workflow-schema`，沉淀流程 DSL、类型、校验器和编译器，供前后端共享。
- 后端新增独立审批流微服务 `services/workflow-api`，技术栈为 NestJS + PostgreSQL，后端运行时使用 Trigger.dev 持久化引擎。
- 流程支持可视化设计、版本发布、单据绑定、审批任务流转、历史审计、节点扩展和后续 BPMN 兼容出口。

## 2. 技术基线

### 前端

- 框架：Vue 3 + TypeScript。
- 包管理：沿用 pnpm workspace。
- 图编辑器：优先 `@antv/x6`，MVP 可用 `@vue-flow/core` 降低开发成本。
- UI 形态：独立 npm 包导出设计器、查看器、任务面板、时间线组件。
- 与低代码集成：通过 schema、事件动作和数据源配置连接单据页面。

### 后端

- 框架：NestJS。
- 数据库：PostgreSQL。
- 数据访问：第一期可沿用 `pg`，稳定后再评估 Prisma、Drizzle 或 Kysely。
- 持久化运行时：Trigger.dev，用于流程 run、人工审批 waitpoint、timer wait、重试、恢复和运行日志。
- 规则表达式：JSONLogic 或受控表达式 DSL，避免直接执行用户 JS。
- 审计模式：运行表 + 历史表 + 事件日志。

### 核心模块

```text

  src/designer

```

## 3. 总体完成指标

- 业务人员可以在页面中拖拽设计审批流程，并发布版本。
- 业务单据可以绑定流程定义，发起后生成流程实例和待办任务。
- 审批人可以通过、驳回、撤回、转交、加签、抄送。
- 支持条件分支、会签、或签、并行分支、服务节点、定时节点。
- 每一次流转都有完整历史、审批意见、变量快照和操作人记录。
- 前端包可被 Nuxt 应用或其他 Vue 应用安装使用。
- 后端微服务具备独立启动、构建、测试和迁移能力。

## 5. MVP 范围建议

第一轮 MVP 不做所有高级节点，建议只做：

- 流程设计器：开始、审批、条件、抄送、结束。
- 后端定义中心：保存、发布、查询。
- 运行时：发起、通过、驳回、结束。
- 任务中心：我的待办、已办、审批意见、时间线。
- 低代码集成：提交审批按钮、审批状态展示、流程查看。

MVP 完成标准：

- 能从低代码单据页面提交审批。
- 能按条件进入不同审批节点。
- 审批人能处理待办。
- 审批结束后单据状态回写。
- 全流程历史可追踪。

## 7. 推荐迭代顺序

```text
阶段 0 -> 阶段 1 -> 阶段 2 -> 阶段 3 -> 阶段 4 -> 阶段 5
       -> 阶段 7 的 MVP 部分
       -> 阶段 6 高级节点
       -> 阶段 8/9 生产加固
       -> 阶段 10 发布交付
```

原因：

- 先把 schema 和包边界定住，避免前后端各写一套流程结构。
- 先做设计器和定义中心，再做运行时，能保证执行器有稳定输入。
- 先闭环简单审批，再扩展会签、并行、定时、服务节点。
- 低代码集成应在 MVP 中尽早接入，否则审批流容易变成孤立系统。

## 8. 风险与控制

- 表达式执行风险：使用受控 DSL 或 JSONLogic，不允许直接执行任意 JS。
- 并发审批风险：任务处理必须使用幂等键和事务锁。
- 流程版本风险：运行中实例必须绑定发布时的不可变版本。
- 组织架构变更风险：审批人解析结果需要保存快照。
- 服务节点风险：外部调用必须有超时、重试、失败补偿和审计日志。
- 历史数据膨胀风险：运行表和历史表分离，后续支持归档。

## 9. 当前下一步

1. `workflow-schema.md`：流程 DSL 与节点协议。
2. `workflow-database.md`：审批流表结构与索引。
3. `workflow-api.md`：定义中心、运行时、任务中心 API。

这三份草案确认后，再进入工程骨架搭建。
